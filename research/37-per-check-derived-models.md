## 1. Question and evidence

Can analint prove a property of one composed `Spec` while exploring fewer fields than its exact slice? In exness-spec, 17 fields and 33 expanded actions produce slices containing 32–33 actions. `Account.balance` has 12 writers alone — five deposits, five withdrawals, close and stop-out. Deposit caps read equity, withdrawals read free margin, and closing realizes P/L into balance. Following the writers of a payment field brings trading and client eligibility into the same graph. The consumer reported approximately 20× growth after adding one boolean **and** widening the P/L range, with memory exhaustion on a 16 GB laptop. (`exness/domain.py:45`, `:87`, `exness/payments.py:55`, `:120`, `exness/margin.py:138`.) [#83](https://github.com/angru/analint/issues/83)

The baseline already includes #79. Merged PR #84 lets qualifying `NoDeadEnd` checks reuse the lock-free graph. On the consumer, the graph answering recovery shrank from 317,184 to 158,592 states. Cold full-check time fell from **69.6 s to 31.2 s** and peak RSS from **435 MB to 228 MB**, with all 45 check statuses preserved. The analysis estimates that five individual safety properties could use graphs of 12, ≤8, 6, ≤176 and 12 states respectively (§8). Whether smaller proof graphs reduce the cost of an entire run depends on diagnostic coverage. [PR #84](https://github.com/angru/analint/pull/84)

## 2. Relations and transferable verdicts

Fix the reference system, check and effective roots. Let `R` contain every state the concrete explorer can visit, including invariant-invalid endpoints. Rejection and transition defects produce no successor. A defect also produces a diagnostic. An accepted successor that violates an invariant is observable, but the explorer stops there. Code references below use `src/analint/validator/` unless qualified. (`kernel.py:228`, `:255`, `:280`, `explorer.py:722`, `:747`, `:781`.)

Resolve canonical `Spec.initial` or the query’s own `given`, `given_any` or `initial` before projection. Enumerate `Initial.vary` and evaluate `where` on full candidates. Preserve candidate-limit, empty-relation and evaluation errors. Check every root against the system and retain its original number, legality and projection. Roots with the same projection may share safety exploration. Each keeps its own blocking findings and witness obligations. A query-owned proof applies only to its roots. (`explorer.py:506`, `:938`, `:1564`, `docs/cli.md:100`.)

**Exact slice.** For the check’s observations, system executions project to slice executions up to steps that leave those observations unchanged, and the evidence deciding the check lifts back to the system. Recovery also requires preservation of goal reachability from each reachable state. Today’s slices run real actions on full contexts. Closure follows writers, reads and constraints, with property-specific rules for terminal locks and disable-only flags. An invalid endpoint caused by an out-of-slice invariant can escape a sliced `NoDeadEnd` check. A system recovery claim therefore needs global invariant support or whole-model confirmation. (`slicing.py:654`, `:696–702`, `:777`, `docs/concepts.md:153`, `docs/cli.md:110`.)

**Over-approximation.** An abstract state is exactly the projection `pi_V(s)` onto the retained variables `V`. Whenever `V` contains a field of slot `r`, it also contains `(r, PRESENT)`. An absent slot supplies no field values. Hidden fields are erased. The full context retained by today’s `project_roots` must never supply a hidden value to an abstract check. (`slicing.py:784`.)

Every concrete root must be represented. Every concrete edge must project to an allowed abstract edge or leave the projection unchanged. Property value, applicability and evaluation errors must agree on represented concrete states. Induction on path length then gives `pi_V(R) ⊆ R_A`, where `R_A` is the abstract reachable set.

Every retained guard, presence guard, terminal lock, hard bound, clamp, lifecycle check, postcondition, payload constraint and pruning invariant must read only `V` at its proper evaluation phase. If a check reads hidden state, drop or weaken it only when successor inclusion still holds. Otherwise widen `V` or use exact execution. Dropping a whole top-level guard conjunct weakens a guard. Dropping a term inside negation or disjunction requires a separate implication proof. A retained pruning invariant can stop expansion only after the endpoint has been recorded and observed.

Erase hidden writes. Each visible write needs its projected update, finite *havoc* admitting every possible concrete post-value, or a verified environment transition (§6). Preserve unwritten values and every possible joint outcome. Evaluate simultaneous right-hand sides against one pre-state, then apply retained field and lifecycle semantics. Postconditions and emitted payloads see the post-state. (`kernel.py:255`, `:322`, `:368`, `:427`, `:493`.)

**Under-approximation.** Choose subsets of the expanded system actions and actual roots. Execute with the full kernel, constraints, invariants and explorer stopping rules. Every resulting path is a concrete prefix from its named root. Witnesses can accumulate across subsets.

For safety, a **clean, complete** proof exhausts the abstract graph without a cap, abstract evaluation error, unresolved transition defect, blocking root finding or relevant exclusion. An excluded action is relevant if it can write `V`, including slot presence. An unknown write set is relevant. An excluded action proved to write only hidden state stutters, provided the other steps satisfy successor inclusion for every hidden valuation. Its diagnostic coverage remains separately reported. Require an applicable concrete root or replayed prefix before promoting safety PASS. Abstract slot creation alone can manufacture applicability. Exact handling distinguishes a never-applicable invariant (`NOT_CHECKED`) from a vacuous query (FAIL). (`state_checks.py:78`, `explorer.py:1387`, `:1426`, `:1517`.)

| Check | Evidence that transfers to the system | Where the reverse inference fails |
|---|---|---|
| `Invariant`, `AlwaysHolds` | A clean, complete over-approximate PASS proves safety. One concrete applicable violation proves FAIL. | Omitting `overdraw` hides a negative balance. Havoc can invent one. |
| `Unreachable(P)` | Clean, complete over-approximate absence proves PASS. One concrete path to `P` proves FAIL. | Omitting the only unlock action hides the target. Dropping its credential guard can invent a path. |
| `Reachable(P)` | PASS needs a concrete witness from **each required legal root**, all root obligations discharged, **and error-free predicate evaluation** on a covering over-approximation of its operands or by exact checking. Evaluation errors take precedence over matches. | A STANDARD witness leaves PRO undecided. Omitting `fund` can lose the only path. An abstract environment credit can invent one. (`explorer.py:1546–1566`.) |
| `DeadActions` | A concrete prefix certifies that an expanded action **entered**, even if its effect then defects. Combine witnesses, decide remaining actions on exact action slices and keep excluded event-input actions unassessed. | Omitting `enable` hides a firing of `use`. Dropping its guard invents one. A safe first firing can precede a defective second one. (`explorer.py:747`, `:1125`, `:1878`.) |
| `NoDeadEnd(G)` | Use exact recovery checking or the PASS certificate in §5. | An abstract credit invents an exit. A fictitious trap invents FAIL. An action subset can omit either a real trap or its only exit. |
| Scenario, flow | Execute the declared example exactly on its own `given`, with its actions, checkpoints, applicable invariants and emissions. The result establishes that example alone. | Weakening a guard can reverse `Expect.FAIL`. Omitting a withdrawal changes the balance at the next checkpoint. (`scenario_runner.py:17`, `:57`, `flow_runner.py:1`.) |

Use exact negative checks for `Reachable` and `DeadActions`. Absence from a complete over-approximation can refute mathematical reachability from a particular root. Inferring deadness additionally needs a graph that preserves action entry, including defective attempts. A graph of successor states alone does not record those attempts.

**Hard bounds and clamps differ.** From `x=0` with hard `x <= 1`, simultaneous `Set(x, 2), Set(done, True)` defects and neither write takes effect. Dropping the bound in a witness model gives a false `Reachable(x == 2)` PASS. Erasing hidden `x` may admit `done=True` in an over-approximation, but only replay can confirm that path. With a saturating upper bound of 1, the same assignment reaches `x=1`. Raw assignment would falsely prove `Unreachable(x == 1)`. Keep the clamped value in the abstract image and respect which side of a one-sided bound remains hard. (`kernel.py:322`, `:368`, `src/analint/models/entity.py:52`.)

## 3. Choosing `V`

Seed `V` with the property’s operands and applicability reads, including quantified slots, aggregates and nested `BoolValue`. Add presence for every retained slot field. Index **all system writers** after parameter expansion. `Add` and `Subtract` read the old target. `Create` and `Delete` change presence and contents. For a visible update with hidden inputs, add its dependencies unless a justified finite havoc domain covers its image. Revisit writers and implicit checks whenever `V` grows. A mixed guard can be dropped as a unit or its inputs retained to preserve a correlation such as tier and cumulative deposits. (`slicing.py:96`, `:129`, `:172`, `:188`.)

**Two roots expose a hidden postcondition.** Let `Initial(vary=[Account.type])` produce STANDARD and PRO roots, both with `balance=0`. Action `credit` adds 10 and has `post=[Implies(type == STANDARD, balance <= 10)]`. The invariant is `balance <= 10`. Two credits from PRO reach 20 and violate it. Projecting to balance merges the roots. If the merged state borrows STANDARD from the first root, its postcondition rejects the second credit and the invariant falsely passes.

The read-set rule rejects that construction because `type` is outside `V`. Dropping the postcondition admits the path `0 → 10 → 20`, which replays from PRO. Widening `V` with `type` keeps the roots distinct and finds the same violation. The same test applies to a hidden lock, presence guard, payload or pruning invariant.

Stop when all projected concrete steps are covered and the property is observable. A capped run cannot establish a havoc domain. An unsupported operation, unjustified domain or widening to the exact cone selects the existing exact plan with all original semantics restored. Matching the exact field set alone does not restore a weakened guard.

## 4. Re-check, replay and trust

Run one speculative safety attempt with a bounded sub-budget. In `verify_invariants`, place it before the existing unconstrained phase 1 as a cheaper first proof. A clean constrained PASS may decide the target’s system status. **Any pruning by an unproven invariant forbids adding the target to `analysis.trusted` or discharging supporting invariants.** Trust lets later slices omit pruning, so a proof that depends on that pruning cannot grant it. Only a clean proof without unproven invariant pruning can grant canonical invariant trust or discharge the selected safety query’s support under today’s conditions. Query-owned roots neither borrow nor grant canonical trust. Explicitly requested invariants still run. (`explorer.py:1244–1282`, `slicing.py:654`, `docs/cli.md:64`.)

A cap, unsupported operation, relevant exclusion, unresolved error or abstract counterexample returns to the ordinary exact pipeline with the **same effective roots and full original per-check budget**. An abstract counterexample also admits concrete replay. Try the original legal roots projecting to its starting state. Execute the original expanded actions, realize any environment steps concretely, check each projected state and evaluate the target at the endpoint. Stop at a rejection, transition defect or mismatch. Observe an invariant-invalid endpoint before stopping there.

**Successful replay publishes system FAIL even if exact search caps.** Report the root, concrete trace and `under-approx: replayed`. The trace need not be shortest. Exact search may supply a shorter counterexample when its budget allows. If no matching root yields a concrete violation, exact PASS dismisses the candidate and exact FAIL supplies the real finding. If replay yields no witness and exact search caps, publish `INCONCLUSIVE` and retain the candidate in attempt metadata. Preserve exact `NOT_CHECKED` and root diagnostics. Speculative findings never enter system defect coverage. Defer iterative counterexample-guided refinement until repeated spurious paths justify its cost. [Clarke et al., abstraction and counterexample-guided refinement](https://www.cs.cmu.edu/~modelcheck/onr/pubs/abstraction03clarke.pdf)

## 5. NoDeadEnd and local recovery

`NoDeadEnd(G)` asks whether every reachable state has a finite path to `G` (`AG EF G`). A prefix can reach a suspected trap. Establishing that every exit misses the goal requires more evidence. Today the explorer scans goal states, walks backwards over edges and reports the first nonrecoverable state in BFS order. (`explorer.py:1489`, `:1771`, `:1816`.)

**Sufficient rule for PASS.** Require all of the following.

1. A complete may-reachable set `A` covers `pi_V(R)`. Goal truth and applicability are exact on `V`, evaluation is error-free on `A`, and concrete applicability, root and diagnostic obligations hold. No excluded action writes `V` or its locks. Any exclusion in the exact recovery slice blocks the certificate. (`explorer.py:1797–1799`.)
2. Seed `W_0` with states known to satisfy `G`. Retain earlier members. Add `v` at rank `i+1` only if **every reachable concrete state represented by `v` is invariant-valid and expandable**, and a named concrete action from every such state has a real accepted successor whose projection lies in `W_i`. The conservative implementation requires a system PASS for every model invariant over the effective roots.
3. Require every state in `A` to enter some `W_i`. From each concrete state of positive rank the certified action decreases rank. Rank zero satisfies the goal, so finitely many concrete steps suffice without a fairness assumption.

For the conservative action proof, keep recovery guards, reads and writes inside `V` and establish all implicit conditions there or through independently verified invariants. These include presence, terminal locks, bounds, clamps, lifecycle edges, postconditions and payloads. An inert non-goal state, hidden terminal lock, overflow on close or environment credit available in only one hidden valuation defeats the proposed recovery step. Failure to construct the ranks requests exact checking.

In #79 each omitted disabler has a lock-free local restorer. Restoration reaches a twin with the same goal and guards at least as permissive. The merged rule checks flag writers on both values and requires a clean, complete PASS with `free_states × 2^flags < budget`. Other outcomes use the full-lock slice. Preserve that budget contract. Compositional nonblocking verification addresses the same need to preserve continuations to marked states under composition. (`slicing.py:580`, `:608`, `explorer.py:1038`.) [PR #84](https://github.com/angru/analint/pull/84) · [Mohajerani, Malik and Fabian, compositional nonblocking verification](https://publications.lib.chalmers.se/records/fulltext/230846/local_230846.pdf)

## 6. User-written views and composition

Keep one explicit reference `Spec`. A named view or per-check `model=` references existing declarations. Compute the property closure **on the system first**. List omitted expanded writers, the fields they write and the dependency that brought each field into scope. Compare roots, constraints and action semantics too. An empty writer list cannot justify a changed root or guard. Label a verified exact slice `exact`, an unchanged subset `under-approx: omitted […]`, and a verified simulation `over-approx: dropped […]`. An environment must admit every enabled projected successor of every omitted writer, including simultaneous updates and unchanged values, or prove the writer stutters. (`slicing.py:684`, `docs/dsl.md:603`.)

Named views need no second system root. Future support for several `Spec` declarations in one import graph requires an explicit reference system and unique view IDs. Reject ambiguity and implicit union. Extend loader naming to explicitly referenced declaration modules outside the entry directory, including already-imported modules. Preserve qualified class identities and existing IDs, resolve collisions explicitly and keep naming independent of membership. Run cross-contract examples on the integrated system. `flow_withdraw_to_regain_unlimited` needs both the payments withdrawal and the subsequent margin action. (`src/analint/loader/python_loader.py:123`, `:145`, `:183`, `engine.py:63`, `exness/margin.py:283`.)

## 7. Report and CLI

Add a per-check `model` object to `analint.check/v1`. Its top-level `relation` identifies the attempt that decided the **system** `status`. A local attempt can set only `local_status`. If there is no deciding system attempt, use `relation: null` and system `INCONCLUSIVE`. Aggregate `verdict`, `passed` and exit code from system statuses and existing blocking system findings. Local verdicts never contribute.

Record `system_id`, `view_id`, `proof_rule`, root source and original numbers, retained fields, dropped elements with locations and reasons, omitted writers, havoc domains and environment proof references. Ordered `attempts` carry relation, backend, budget, completeness, status and state count. `recheck` identifies the exact retry and outcome even when replay decided FAIL. Preserve existing `slice` semantics for exact slices. Keep derived fields and candidate traces in `model`, reserving system traces for concrete evidence.

```text
PASS deposits_within_tier [system exness, proved via over-approximation]
FAIL balance_limit [system exness, under-approx: replayed, init #2, trace may not be shortest]
INCONCLUSIVE archived_is_flat [system exness, replay failed, exact re-check capped]
INCONCLUSIVE deposits_within_tier [system exness]; local PASS on view payments — not valid for the system: close_position writes Account.balance
```

`--check` selects obligations on the same system. Under #81-style selected coverage, report assessed and unassessed actions in `model_coverage`. Preserve whole-system structural validation, relevant transition diagnostics and unfiltered coverage. A firing witness cannot discharge later defects in that action. (`docs/cli.md:38`, `:90`, `explorer.py:1125`.) [#81](https://github.com/angru/analint/issues/81) · [#53](https://github.com/angru/analint/issues/53)

Key cached attempts by relation, transformation version, actions, domains, constraints, roots and inert provenance, budget and engine semantics. Bind certificates to the system digest and obligation. Isolate speculative graphs from exact superset reuse. Initially use TLC on supported exact fallbacks. An abstract TLC attempt later requires a faithful export and the same transfer rule. Refusal or timeout leaves it undecided. Current TLC excludes `NoDeadEnd` and `DeadActions`. (`exploration_cache.py:228`, `explorer.py:1086`, `tlc_fallback.py:7`.)

## 9. Phasing and acceptance

1. Start with automatic over-approximation for `Invariant` and `Unreachable`, projection, guard weakening, hidden-write removal, widening for hidden reads, replay and one exact retry. **Accept phase 1 on correct system verdicts, explicit deciding-relation labels and smaller proof graphs on `--check` runs.** Land #81-style coverage before or alongside end-to-end selected-run performance evaluation.
2. Extend `tests/test_slicing.py` with differential checks against exact execution on every example and benchmark. Require agreement on decisive exact results, root attribution, concrete diagnostics and replayable failures. Document a strengthening from `INCONCLUSIVE` to PASS when the smaller proof completes within budget or every excluded action provably stutters on `V`. Gate replayed FAIL independently against the concrete kernel, including when exact BFS caps. Plant the two-root postcondition, hidden writers, simultaneous swaps, hard overflow, one-sided clamps, hidden locks, absent slots, invalid endpoints, exclusions, predicate errors and later firing defects. Exercise selected/full, cold/warm cache and supported TLC paths.
3. On a separate runner, compare the frozen consumer and wider-P/L variant against `4a288bb` at equal budgets. Record proof fields and states, distinct graph builds, reuse, retries, coverage work, total time and peak RSS. Measure selected coverage separately. Claim an unfiltered gain only after demonstrating reduced or reused coverage work with defect parity. [#68](https://github.com/angru/analint/issues/68)
4. Extend to `AlwaysHolds`, finite havoc, concrete witness subsets, named views and verified environments in reviewable steps. Gate recovery on a working restorer and planted hidden guards, defects and goal-free traps. The principal risks are false system PASS, lost diagnostics and repeated exact retries. Symmetry, partial-order reduction and symbolic backends remain separate experiments.
